# 性能调优 · 让这个包在你机器上真的流畅

> 203 个模组 + 史诗地形 + 2048 区块视距，靠的不是"堆内存"，是分层卸载：
> **近处交给 Sodium，远处交给 DH，逻辑交给 Lithium，内存交给 FerriteCore。**

---

## 一、JVM 参数（PCL2 里直接粘）

PCL2 → 版本设置 → 高级设置 → **JVM 参数**，整行替换：

### 8~12 GB 内存的机器（推荐）

```
-XX:+UseG1GC -XX:+ParallelRefProcEnabled -XX:MaxGCPauseMillis=130 -XX:+UnlockExperimentalVMOptions -XX:+DisableExplicitGC -XX:+AlwaysPreTouch -XX:G1NewSizePercent=28 -XX:G1MaxNewSizePercent=45 -XX:G1HeapRegionSize=8M -XX:G1ReservePercent=18 -XX:G1HeapWastePercent=5 -XX:G1MixedGCCountTarget=4 -XX:InitiatingHeapOccupancyPercent=22 -XX:G1MixedGCLiveThresholdPercent=90 -XX:SurvivorRatio=32 -XX:+PerfDisableSharedMem -XX:MaxTenuringThreshold=1 -Dusing.aikars.flags=https://mcflags.emc.gs -Daikars.new.flags=true
```

### 16 GB 以上（用 ZGC，大视距更稳）

```
-XX:+UseZGC -XX:+ZGenerational -XX:ZCollectionInterval=5 -XX:+AlwaysPreTouch -XX:+DisableExplicitGC -XX:+PerfDisableSharedMem
```

### 内存分配建议

| 内存总量 | 分配 | 说明 |
|---|---|---|
| 8 GB | 4 GB | 只能玩 12 区块近景，DH 关掉 |
| 16 GB | 7~8 GB | 甜点：DH 512 区块 |
| 32 GB | 10~12 GB | DH 1024~2048 区块 |
| 64 GB | 14~16 GB | 别超过 20 GB，G1 会变慢 |

> 别把内存塞满物理内存，Windows 需要留 2~3 GB。

## 二、Distant Horizons（超远视距的核心）

进游戏后：`Esc` → `选项` → `Distant Horizons`（或按 `H`）

### 目标配置

| 选项 | 值 | 为什么 |
|---|---|---|
| **LOD 距离** | 512（中配）/ 1024（高配）/ 2048（顶配） | 这是你能看到多远 |
| **最大 LOD 区块数** | 4000 / 8000 / 16000 | 内存换视距 |
| **LOD 生成线程** | CPU 核数 − 2 | 8 核填 6，16 核填 12 |
| **LOD 数据保存** | 开 | 否则每次重算，卡到爆 |
| **垂直质量** | 中 | 高会翻倍生成耗时 |
| **水平质量** | 高 | 远景轮廓主要靠它 |
| **透明水** | 开 | 史诗地形要看到海 |
| **远处方块光照** | 关 | NeoForge 下开销大 |
| **洞穴剔除** | 开 | 省一半算力 |

### 配合的 Sodium 设置

- 渲染距离：**10~12**（不要开 32，那是 DH 的活）
- 模拟距离：**8**（服务端也这么设，见 `server.properties`）
- 图形：**Fast**（DH 会补远景，近景精细度可以降）
- 云：**Fast** 或 **关**
- 平滑光照：**关**（配 Iris 光影时开）
- 实体阴影：**关**
- 区块构建线程：**默认**（Sodium 自己会算）

### 光影

Iris 已装。推荐用轻量光影（Complementary Reimagined "Performance" 档），
**不要**用重度体积云/光追光影 —— DH 远景 + 重光影 = 掉 40 帧。

## 三、服务端（`server.properties` 已调好）

| 项 | 值 | 作用 |
|---|---|---|
| `view-distance` | 10 | 服务端只发 10 区块，远处靠客户端 DH |
| `simulation-distance` | 8 | Create/AE2 大机器不会吃掉整个 TPS |
| `entity-broadcast-range-percentage` | 80 | 联机带宽省 20% |
| `sync-chunk-writes` | false | SSD 必开，机械硬盘请改 true |
| `max-tick-time` | 60000 | 单 tick 不误杀 |
| `pause-when-empty-seconds` | 0 | 无人时不冻结（避免回来卡一波） |

### 服务端额外建议

1. 预生成地图：`/chunky radius 2000` + `/chunky start`（开服前跑一次，之后不再卡）
2. 用 `spark` 排查：`/spark profiler start` → 玩 5 分钟 → `/spark profiler stop`
3. 生物上限：如果养了太多动物，`/kill @e[type=!player,type=!item,distance=..]` 分批清理
4. 定期重启（4~6 小时），AE2 与 Create 长时间运行会有内存碎片

## 五、卡顿自查表

| 现象 | 原因 | 处理 |
|---|---|---|
| 一进世界卡 10 秒 | DH 在算 LOD | 正常，站着别动等它算完 |
| 跑图时一顿一顿 | LOD 生成线程太多/太少 | 线程 = 核数−2，重进世界 |
| 夜晚掉帧 | 怪物多 + 火把粒子 | 关"粒子：最少"，`/gamerule doMobSpawning` 别关 |
| 打开 AE2 终端卡 | 网络里物品种类过万 | AE2 配置里开"终端虚拟滚动" |
| 火车开动卡 | 列车实体 + 区块加载 | Steam 'n' Rails 设置里降"列车渲染距离" |
| 内存一直涨 | 区块缓存 | 装 `FerriteCore` 已在；`/spark heapsummary` 看是谁 |
| 联机别人瞬移 | 带宽/延迟 | 服务端 `entity-broadcast-range-percentage=70` |

## 六、低配机降级路线

按顺序关，直到帧数稳住：

1. DH LOD 距离 512 → 256
2. 关光影（Iris 里选 "Off"）
3. Sodium 渲染距离 8
4. `Particle Core` 配置里把粒子降到 25%
5. 关 `Ambient Sounds` / `Sound Physics`（音频线程也吃 CPU）
6. 关 `Falling Leaves` / `Particle Rain`
7. 最后才降 JVM 内存（内存不是帧数的解药）
