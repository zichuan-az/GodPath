# 神格之路：项目分析与实测报告

日期：2026-11-10（北京时间）。维护版本：3.0.1。

## 项目目标与结构

既有目标是“前期硬核求生 → 科技、铁路、魔法和庄园发展 → 六法则 24 神物 → 磁石成神”，不依赖任务书。核心玩法由 KubeJS 实现，`work/godpath/` 中的 Java 工程目前只是空的模组入口，不是神物系统的实际实现。

`pack/` 是游戏覆盖文件源，`scripts/final_mods.json` 是下载文件及版本锁定源。此前 `pack/mods.json`、生成器和多个 `dist/` 历史目录不同步，容易出现“源码已修但用户装到旧文件”的情况。本轮统一了两个正式生成器，补充根目录 README、行为测试和产物校验。

## 已修复问题

| 问题 | 根因与修改 |
|---|---|
| 服务端脚本无法正确建立公共库 | KubeJS 2101 的服务端 `global` 只读；改为服务端共享作用域的变量和函数。官方迁移说明明确了这一限制。[KubeJS 7.0](https://kubejs.com/wiki/other/major-updates/7.0) |
| 普通玩家神物失效 | 实体 `runCommandSilent` 沿用玩家权限；现在由服务器执行受控的固定命令，以玩家为执行者和位置上下文，不授予 OP。删除了可能误作用于最近玩家的回退。 |
| 服务端判定错误 | 兼容布尔字段和方法，避免把 `isClientSide` 方法对象本身视作 true。 |
| 药水和属性命令无效 | 去掉 `effect give` 不支持的额外参数；1.21.1 属性改用 `minecraft:generic.*`。 |
| 冷却首用失败、真实运行中时间为 NaN | 检查是否存在冷却记录；优先使用 KubeJS 重命名后的 `level.getTime()`，并拒绝无效时间。 |
| Boss 偶尔只掉一个碎片 | 将固定 Boss 奖励置于普通随机掉落之前；精确匹配实体 ID，补充末影龙及主要模组 Boss，避免把凋灵骷髅当 Boss。 |
| 幼苗、蔬菜箱、稻米袋可刷丰饶碎片 | 只匹配明确的作物 ID 和成熟年龄；农夫乐事番茄、水稻、稻穗使用本机 jar 确认的年龄 3。 |
| 神物进度能重复计数 | 读档时只保留有效、唯一的 24 神物 ID；拒绝登记未知 ID。 |
| 重生丢属性、卸下刀仍保留刀阶 | 根据实体上真实 modifier 恢复或移除，校正已有错误数值，不再以持久布尔标记代替属性状态。 |
| 成神移速与说明不符 | 从固定加 0.03 改为基础移速 +15%；旧值会在属性同步时被校正。 |
| 重复点击、退出导致仪式状态异常 | 增加进行中状态，防止重复排程；退出、重生和登录清理进行中状态。属性恢复不重复发奖励。 |
| 锚点跨维度传到错误位置、零坐标失效 | 同时保存维度和坐标，按键是否存在判断锚点。旧坐标需重新记录以补充原维度。 |
| 催熟改变全服随机刻且错误恢复为默认值 | 改为有限范围内支持作物的成熟度修改，保留其他方块属性，不改变全服 gamerule。 |
| 刀技伤害命令无法执行、方向不符 | `damage` 必须指向单实体；改为逐个 UUID 结算，方向技能筛选前方窄通道，排除动物与玩家。 |
| 家园跨维度判定混用 | 统一维度 ID 表示，家园提示键也包含维度；脆弱期家园豁免检查相同维度。 |
| 下载和打包不一致 | 清单从旧 203 项同步到当前锁定项；拒绝非 jar 和重名文件；按真实客户端/服务端元数据标记环境；修正输出版本文件名。 |
| Windows 下载器可卡死或假成功 | 限定线程数 1–32；向后台运行空间传入绝对下载目录；存在失败时返回非零退出码。 |

## 真实启动中复现的模组冲突

1. **剑翔与 Epic Fight API 不匹配**：缺少 `BuildCameraTransform$Post`。剑翔官方版本说明测试的是 Epic Fight 21.14.1，包内为 21.17.3.1。本轮移除这个可选扩展，保留 Epic Fight 与拔刀剑主线。[上游版本](https://modrinth.com/mod/epic-fight-sword-soaring/version/IUHijzQc)
2. **Structory Towers 1.0.17 元数据缺失**：原文件缺少有效 NeoForge 加载器声明。改用元数据正常的 **1.0.15 原版**，避免让新用户依赖本机手工修补的 jar。[上游文件](https://modrinth.com/datapack/structory-towers/version/lefqbuOP)
3. **Distant Horizons / Chunky 启动时序崩溃**：新世界在区块提升到 FULL 阶段报 `Chunky is not loaded`。移除可选预生成器 Chunky，保留 Distant Horizons。
4. **KubeJS Create 适配与当前配方格式冲突**：嵌套配方转换出现错误。本包自定义配方全为普通合成，并未使用这项适配；移除适配后，自定义 31 个配方全部正常加入。
5. **Iris 1.8.12 / Sodium 0.8 渲染崩溃**：缺少旧 Sodium GUI 类。采用官方说明支持 Sodium 0.8 的 **Iris 1.8.14-beta.1**，保留光影。[上游版本说明](https://modrinth.com/mod/iris/version/KduFYu4t)
6. **误选整合包项目**：`Create & things 3.3.3.mrpack` 被当成模组放进下载清单；移除。它不是可直接放入 `mods/` 的 jar。

修复版最终锁定 **238 个模组**。未对其他模组进行批量升级。

## 仍需后续完善的内容

本轮完成的是既有主线的稳定性修复，并未把早期图鉴中的全部设计承诺都视为已实现。仍有明确差距：

- 原声回响的结构扫描反馈、秘法残页对正确目标附魔，尚未形成可靠的玩家流程。
- 部分早期图鉴中的摔落减免、经验加成、结构高亮、列车提速和攻击雷击描述，与当前实现不一致。新的主说明已明确文档状态；后续应逐件确定数值并实现。
- 扫描每秒登记神物；快速合成消耗一阶物品前，应先确认共鸣提示。未来可以改为获得/合成事件即时登记。
- Boss 固定奖励依赖明确的实体支持名单，不代表整合包中每个新增强敌都已纳入。
- 第三方模组仍有未安装可选联动的资源、配方警告。没有宣称第三方完整日志零错误。
- 没有进行所有维度/Boss 的逐项通关、光影视觉检查、长期多人服务器压力测试或帧率基准测试。

Windows 自动界面检查被自动审批拒绝（未获准控制 Java 窗口），因此本轮使用游戏内执行结果及日志完成验证，没有把画面检查列为已完成。
